Rerunning it

Running /observe again reproduces these figures exactly: it finds every model output already done and starts no agent (the rerun after the submitted run took 19 s), and CI rebuilds every code step from the committed model outputs on macOS, Linux and Windows and fails if any committed output changes. A fresh run, /observe --force, asks the model again for its judgement: the list of processes, which messages belong to which, and the minutes one round of each takes. Like two analysts, two fresh runs do not judge identically, so the processes and the estimated dollars move with them. The counting and the arithmetic on any given judgement are exact. The counted part, email actions priced at published minutes, moved little; most of the spread is in the estimated work. Part of the spread is ours rather than the model's: agent instructions and the scoring code changed between the earlier runs (they also rounded each part on its own, so their counted and estimated parts can miss the total by a few cents), and a process with no accepted estimate adds nothing to the estimated part. In a real engagement the client would approve the process list and the estimates once and lock them (an estimates file already replaces the model's figure for the processes it names: How to use), and later runs would move only when the mail does.

What out/ holds

  • The prepared corpus facts: the manifest of every message with its Git blob ID, the parsed messages, the duplicate groups, the threads and the people.
  • Every model output and its check: the taxonomy, the extractions and their validated copies, the merge table, the syntheses, the drafting briefs and the drafts, each with a ledger file recording its cache key.
  • What code made from them: the rollup, the scored opportunities, the drafted documents with their evidence, the dashboard data and the report.
  • The run logs.

The dashboard runs on these files with no model call: node obs.mjs serve. Because the ledger is committed, the first /observe in a fresh clone finds every job current and starts no subagent; /observe --force runs cold. Warm and cold runs has the detail.

The dashboard copy on this site

The dashboard here is the run's built dashboard copied as it is, with one change: its page is marked as the static copy, so the message viewer reads each message from a file beside the page instead of asking the local server. Every message of the manifest was written once through the same corpus reader the server uses, in the shape the server returns.

The copy holds 3,240 messages, 3,316 files in all, 15.5 MB. Open it.
