## Purpose

Use this request form when gas is flowing at a meter or on a pipeline and there is no valid Sitara deal for the month: a ticket expired, ended mid-month, was never created, or is not released. One complete request gives the desk everything it needs to create, extend, zero out or correct the ticket and to send back the deal or track number, so allocations and the Unify volume drafts can clear.

## Who fills it in

The requester fills it in: the scheduler, volume analyst or accountant who found the meter or pipeline with no valid deal, an expired ticket or an allocation exception. The requester owns the request until the ticket is confirmed released and flowing into Unify.

The desk (the trader or logistics coordinator) fills in the last block, "Desk response", and decides whether to extend or create. The owner for the pipeline, listed in the routing table at [location of routing table], is the person who receives the request. Set up that routing table first and keep it current, with one row per pipeline or meter group and one named owner each, so requests are not passed between people.

## When

- Send a form as soon as flow is found with no deal, an expired ticket, an allocation exception that needs a deal extended, or a deal that is still not released.
- Send one form per meter or pipeline. List several deal numbers on one form only when they are the same change for the same counterparty.
- If there is no reply [proposed: by the end of the same day], send one reminder to the same owner, then escalate to the desk lead [name or role].
- Check the effective date and price against the source before sending. Wrong terms in the first request mean a second request.

## Where it goes

- Send the request by email to the owner named for the pipeline in the routing table, with the desk copied. Put the meter number and action in the subject line, for example "[action]: meter [meter number], [pipeline]".
- The desk enters or changes the ticket in Sitara and replies on the same thread with the deal or track number.
- The requester checks Sitara and Unify, fills in the confirmation block and replies on the same thread. Keep the thread as the record of the change.
- If the ticket is still not released after the desk reply, say so on the same thread and name the deal number. If the owner is unclear or the request is redirected, copy the desk lead and ask for the owner to be added to the routing table.
- If terms in the form turn out to be wrong (effective date or price), send a corrected form on the same thread and mark it "corrected".
- If the person named for a pipeline is disputed (different people have been given as the one who enters these deals) [confirm still in force], the desk lead decides and updates the routing table.
- Where the accounting arrangements for a new deal must be set up, name the group or person responsible on the form's notes line; volume management as a group and individual colleagues have both been named for this, so confirm which one before sending.
